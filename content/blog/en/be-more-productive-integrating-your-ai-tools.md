<section>
<p class="text-lg font-medium text-gray-800 leading-relaxed mb-4">
We were sold the idea that the most productive developer is the one who generates the most code. But when did we start measuring coding success by lines of code output rather than functionality?
</p>

<p>
With tools like GitHub, Copilot, Cursor, and other AI-powered coding assistants, generating code has become much faster. We can build components, create endpoints, write tests, and develop entire features in less time.
</p>

<p class="mt-4">
But that doesn't mean we're delivering more efficient software. It simply means AI tools helps us produce code faster. Writing an implementation is only one part of the job. We need to understand it, verify its results, integrate it with the existing system, and maintain it as requirements change.
</p>

<p class="mt-4">
AI is transforming the way we code. The challenge is making sure that this additional speed translates into real productivity.
</p>
</section>

<div class="h-px bg-gray-100 my-8"></div>

<section>
<h2 class="text-2xl font-bold text-gray-900 mb-4">We need more sophisticated AI tools that pays attention to every detail.</h2>

<p>
Consider, for example, a service that processes payments. An assistant can quickly generate an endpoint, a service layer, and its unit tests. However, the implementation still needs to address issues such as request idempotency, transaction atomicity, external error handling, and protection against duplicate transactions.
</p>

<p class="mt-4">
These requirements are not secondary details. They are part of the system's correct behavior. That's why real productivity must be evaluated end to end, from the moment work begins until the functionality is integrated, validated, and ready to use.
</p>
</section>
