think4ever.com — PostHog Analytics Setup

This adds production growth metering to the marketing website. It sends events to the PostHog "Default project" (ID 347860, US Cloud) so the journey think4ever.com → CTA → portal registration is measured end-to-end. Everything is packaged in one file that sits next to these instructions: t4e-analytics.js.

What to put

The single file t4e-analytics.js (in this folder). Do not modify it. It already contains the PostHog loader, the project token, all event tracking, and safety gates.

Where to put it — website source (Next.js)

Step 1. Copy t4e-analytics.js into the website project's public/ folder, so it is served at https://think4ever.com/t4e-analytics.js.
Step 2. In the root layout (app/layout.tsx or app/layout.js) load it on every page: 
import Script from 'next/script'

// inside the layout component, anywhere in <body>:
<Script src="/t4e-analytics.js" strategy="afterInteractive" />
Step 3. Build and deploy the site as usual, then clear the Sucuri cache (Sucuri dashboard → Firewall → Clear cache), otherwise visitors keep getting the old cached pages.
If deploying without a rebuild (patching the already-exported HTML on the server): upload t4e-analytics.js next to index.html in the docroot, and add <script src="/t4e-analytics.js" defer></script> just before </head> in every .html file (homepage and all docs/*.html pages). This is temporary — the next site rebuild wipes it, so the Next.js source fix above is the real one.

What it does

EventFired whenProperties
marketing_page_viewedEvery page view (incl. client-side navigation)page, path, url, referrer
marketing_cta_clickedAny link to portal.think4ever.com, or any element with a data-cta attributepage, path, cta_location, cta_text, destination

UTM parameters (source / medium / campaign, etc.) and first referrer are captured automatically on landing and stored in a cookie on .think4ever.com, so campaign attribution, the anonymous identity and the session all survive the jump to portal.think4ever.com and into registration.

Built-in safety

  • Sends nothing from file://, localhost, or private/internal hosts — impossible to pollute production data from a local copy.
  • Employee / QA browsers: open any page once with ?t4e_qa=1 appended to the URL — that browser is permanently excluded. ?t4e_qa=0 re-enables it.
  • The embedded token is a write-only public key — safe to ship in page source.

How to verify after deploy

1. Open https://think4ever.com/?utm_source=qa&utm_medium=test&utm_campaign=setup_check in a normal browser (not one flagged with ?t4e_qa=1).
2. In DevTools → Network, confirm requests to us.i.posthog.com appear.
3. Click the hero "Get Started" CTA.
In PostHog (project 347860) → Activity, within a minute you should see marketing_page_viewed then marketing_cta_clicked from the same person, with utm_campaign = setup_check and a https://think4ever.com/... URL.
